# Contributing to ion-repo

*English · [Français](#en-français)*

Thanks for wanting to help! Bug reports, ideas, docs fixes and code are all welcome.

## Issue or pull request?

- **Pull request directly** for anything small and obvious: a typo, a broken link, a clear bug
  with a local fix, a missing check. Add the test that would have caught the bug.
- **Issue first** for anything bigger: a new stack, a new command, a change to what generated
  repos look like. ion-repo is a generator — a change in `template/` lands in every repo built from
  it — so it is worth agreeing on the approach before you write code.
- Not sure? Open an issue, or a draft PR with a short explanation. Both are fine.

Fork the repo and open your PR against `develop` (the default branch); `main` only receives
releases. The maintainer is the only one who merges.

### From Claude Code

Repos generated by ion-repo ship the `repo:report` skill (`/repo:report <what went wrong>` in any
repo with the `ion-repo` plugin). When Claude Code hits a defect that comes from
ion-repo, the skill checks that ion-repo is up to date, searches the existing issues and PRs, then
drafts the issue or the PR in English, with nothing private from your repo. It posts only once
you have read it and said yes. These reports follow the rules above and are reviewed like any
other.

## Development setup

You need [uv](https://docs.astral.sh/uv/) and git. Python 3.14 is downloaded by uv if needed.

```sh
git clone https://github.com/antoine-tena/ion-repo
cd ion-repo
uv sync
uvx pre-commit install           # ruff before each commit, mypy before each push
uv run ion-repo                      # the CLI, straight from your checkout
ION_REPO_TEMPLATE=$PWD uv run ion repo new /tmp/demo --no-github   # try your template changes
```

Checks (the same ones CI runs):

```sh
uv run ruff check . && uv run ruff format --check src tests
uv run mypy src tests
uv run pytest -q                 # renders every stack combination, ~20 s on all cores
```

## Where things live

| Path | What |
|---|---|
| `src/ion_repo/` | The `ion-repo` CLI, one module per command (`new.py`, `update.py`, `settings.py`…). |
| `src/ion_repo/charter/` | The `charter` rule engine. |
| `copier.yml`, `template/` | The Copier template: questions and generated files. |
| `.github/workflows/` | Reusable workflows called by generated repos. |
| `plugins/` | Claude Code plugins (`ion-repo`, `django`, `nuxt`, `vps`…). |
| `tests/` | `test_template.py` renders the template for each stack; `test_docs.py` keeps the READMEs in step with the code. |

## Good first contributions

- **A new stack** (backend or frontend) following an existing one in `template/`.
- **Docs:** examples, a tutorial, fixing anything that confused you.
- Look at issues labelled
  [`good first issue`](https://github.com/antoine-tena/ion-repo/labels/good%20first%20issue) and
  [`help wanted`](https://github.com/antoine-tena/ion-repo/labels/help%20wanted).

## Conventions

- Small, focused commits; prefixed titles (`feat:`, `fix:`, `docs:`, `chore:`), 50 chars max.
- No `Co-Authored-By: Claude` or `Claude-Session:` trailer, no `--author`: the commit is yours,
  whatever tool helped write it.
- No `pip`, no `docker` anywhere: uv for Python, pnpm for JavaScript, podman for containers.
- Never commit secrets or real personal data.
- Code, comments, messages and docs are in English (a few older comments are still in French);
  `README.fr.md` and `docs/reference.fr.md` are their French versions.
- A change updates the docs in its branch: [`docs/reference.md`](docs/reference.md) (and its
  French version) for what it adds, the README when what ion-repo is for changes. Images come from
  `uv run python scripts/screenshots.py`; `tests/test_docs.py` fails when one is out of date.

## Code of conduct

ion-repo follows the [Contributor Covenant](CODE_OF_CONDUCT.md). Be kind and assume good intent.
Harassment or personal attacks are not tolerated; report them privately to the maintainer,
through [GitHub's private reporting](https://github.com/antoine-tena/ion-repo/security/advisories/new).

## En français

- **PR directe** quand la correction est claire et localisée (depuis un fork sans droits
  d'écriture), avec le test qui l'aurait détectée.
- **Issue d'abord** quand il faut trancher entre plusieurs voies ou qu'on ne sait pas corriger :
  une PR sur un choix pas encore fait risque d'être refaite. C'est la règle [REPORT-TO-ION-REPO]
  des chartes générées.
- Depuis Claude Code, le skill `repo:report` vérifie qu'ion-repo est à jour, cherche ce qui
  existe déjà, rédige l'issue ou la PR en anglais et ne publie rien sans l'accord de
  l'utilisateur.
- Les PR visent `develop` ; `main` ne reçoit que les versions.
- Contrôles : `uv run pytest -q`, `uv run ruff check`, `uv run ruff format --check`,
  `uv run mypy src tests`.
