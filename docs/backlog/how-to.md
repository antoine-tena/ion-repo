# 📖 How to use (humans and agents)

This folder is ion-repo's only work list. [README.md](README.md) is the index (north star, next
free ID, pointers); [tickets/](tickets/) holds one file per open ticket,
[releases/](releases/) one file per planned release (`ion repo backlog` draws the plan); [done.md](done.md), the closed tickets, one
line each, most recent first (written by `/repo:backlog done`), [rejected.md](rejected.md), what
was turned down, dropped or ruled out for good, and [urgent.md](urgent.md), what only a human on
the team can do (access, payment, decision), one checkbox per action (counted by the status
line). [vision.md](vision.md) and [kiln-score-the-thesis.md](kiln-score-the-thesis.md) are where
the tickets come from.

An audit writes its dated report next to these files (`audit-<topic>-YYYY-MM-DD.md`) while it
runs, copies its open findings into tickets (with a pointer to their lines), then moves to
`docs/_archive/YYYY-MM-DD-topic/`. Archives **can be read, but everything in them is old and must
be checked** against the current code; they are never edited.

**A ticket** = one file, `tickets/ion-repo-T-NN-<slug>.md` (a few lowercase words of the title,
kept if it changes): a heading, the fixed lines, then the details. The ticket is the brief of a
worker, often a Sonnet subagent that starts with no context: it names its files, so the worker never
explores to find them.

    # ion-repo#T-NN · Short title that says what to achieve
    - **Type**: task
    - **Priority**: 🟡 normal
    - **Status**: todo
    - **Opened**: YYYY-MM-DD
    - **Effort**: S · **Owner**: … · **Due**: —
    - **Session**: sonnet medium
    - **Touches**: backend events; migration no; API contract yes; front crew/
    - **Release**: <release-name>
    - **Origin**: where it comes from

    Why, what to do (as a `- [ ]` checklist when there are several steps).

    ## Files
    - `path/to/module.py` — edit
    - `path/to/rules.py` — source of truth (read it, never duplicate it)
    - `path/to/generated.ts` — generated by `<command>` (never edited by hand)
    - `tests/test_module.py` — test (to write or extend; expected values for money, migrations, personal data)

    ## Done when
    What is checked before the merge.

- **ID** `ion-repo#T-NN`: stable, never reused, always written whole, here too, and quoted as is
  in commits and pull requests (decision of antoine, 1 November 2026; a branch carries the number
  without the prefix, then what it holds, `fix/t07-season-guide`, since 18 November 2026; tickets opened before 16 October 2026 were `AF-NN`, same number). A ticket of
  another repo carries that repo's name (`ion-learn#T-03`). The next free one is in the index
  (`Next free: ion-repo#T-NN`), moved on by each new ticket. A renamed repo: `ion repo set name=…`
  moves its own prefix in its own tracking, file names included, same numbers; citations in other
  repos keep the old name, which the forge redirects; old commits are never rewritten.
- **Type**, one of: `bug` (something is broken); `improvement` (it works, it could work
  better); `idea` (nothing exists yet, to be explored); `task` (work that is neither: a release,
  a decision, a check).
- **Priority**, one of: `🔴 critical` (now), `🟠 important` (before the north star),
  `🟡 normal`, `⚪ background` (long-running work, debt, ideas still to be explored).
- **Status**, one of: `todo`; `in progress — branch <name>, since YYYY-MM-DD`;
  `blocked — waiting for <who or what>`; `to verify — <where>`.
- **Effort**, in Claude Code session time on the Pro plan ion-repo is built with: XS under
  15 minutes, S about half an hour, M about an hour, L two to three hours (split it when it can
  be split). Measured on kiln: on 16 October 2026, 9.3 session-hours shipped four promotions and
  the move to English (about 8,000 lines changed): some twenty times faster than the former
  estimates in human time.
- **Session**: `<model> <effort>`: the model of the Claude Code session that works the ticket
  (`sonnet` by default, `opus` when the work needs it) and its effort (`low`, `medium`, `high`,
  `xhigh`, `max`); `, <branch>` may end it. Without the line: `sonnet`, XS and S `low`, M and L
  `medium`, the branch `<type>/tNN-<slug>`. The former `· **Session**: medium, fix/two-coaches`
  on the Effort line is still read; `ion repo update` moves it. `ion repo session` reads it;
  `ion repo session --subagent <ID>` prints the brief of the `ticket` subagent.
- **Touches**: backend apps, migration yes or no, API contract yes or no, front folders: what an
  orchestrator reads to know which tickets may run at the same time.
- **Release**: the name of the release file the ticket is planned in, the only place that says it.
- **Files**: one line per path with its role: `edit`; `source of truth` (read it, never duplicate
  it); `generated by <command>` (never edited by hand); `test` (to write or extend, with expected
  values for money, migrations, personal data). Checked when the ticket is written; the worker
  still verifies them, but no longer explores. **Done when**: what the orchestrator checks.
- **Budget**: the Pro quota restarts every Tuesday at 8:00 (Paris). It lasted 42 session-hours
  the week of 6 October and 33 the week of 13 October (limit reached on Friday at 14:03), all
  projects together; a 5-hour window runs out after 2 to 3.5 hours of work. kiln plans on
  25 session-hours a week, about 7 per release, spread over the week (about 5 a day, all
  projects): spent by Friday, it leaves the Saturday and Monday releases without budget. No
  fleet of subagents, no headless run without a budget said beforehand.
- **Releases**: one file per planned release in [releases/](releases/), `<release-name>.md`: a
  stable slug of its title (a few lowercase words, kept when the version changes), a
  `- **Version**: vX.Y.Z` line (renumbering edits that line, nothing moves), why, a `## Handoff`
  the orchestrator overwrites at each relay. It lists no ticket: each ticket names its release,
  and `/repo:backlog plan` places every open ticket and every kiln score idea; numbers are planned,
  not promised, until the candidate is cut. The plan's notes and what shipped:
  [releases/README.md](releases/README.md). The files written before (`vX.Y.Z.md`, with their
  ticket lines) are migrated by `ion repo update`; read as they are until then.
- **Closing a ticket**: delete its file (and, in a release not migrated yet, its line), and add a line at the
  top of [done.md](done.md):
  `- **YYYY-MM-DD** · ion-repo#T-NN · Title — what was done (branch) · opened YYYY-MM-DD`.
- **Details in archived audits**: when a ticket quotes lines of `docs/_archive/`, the original
  finding is there in full; it is old, check it against the current code.
- **Map**: `ion repo backlog`, production's version read from git, then each release in version
  order with its tickets (ID, status, size, session, touches, title), then the unplanned;
  `--release <name>` prints one. Then read only the files of the tickets involved.
