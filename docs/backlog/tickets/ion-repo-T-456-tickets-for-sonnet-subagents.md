- **Origin**: review of the three-role organisation (global CLAUDE.md of 2026-11-26): an Opus planner writes tickets, an Opus orchestrator hands each to a Sonnet subagent that starts with no context

Why: a subagent pays for every turn it spends finding files (cost ≈ turns × context), and today's
tickets only give "hints". Releases list their tickets by hand and the backlog README holds live
state by hand: both already drift (annski's README said production ran v2.16.1 while `main` was
tagged v3.2.1). And `ion repo session` still prints `claude --model claude-opus-5-5`, a prompt
that merges by itself and asks the user, which a subagent can neither do nor should.

## Ticket format (template, parser, skill)
- [x] Two new fixed lines after **Effort**: `- **Session**: <model> <effort>` (model `sonnet` by default, `opus` allowed; replaces the optional `· **Session**:` at the end of the Effort line; parser reads both during the migration) and `- **Touches**: …` (backend apps, migration yes/no, API contract yes/no, front folders), which an orchestrator reads to know which tickets may run in parallel.
- [x] A `- **Release**: <release-name>` line: the ticket names its release, the only place that says it.
- [x] A `## Files` section, one line per path with its role: `edit`, `source of truth` (where the value or rule lives: read it, never duplicate it), `generated by <command>` (never edited by hand), `test` (to write or extend, with expected values for money, migrations, personal data). Paths are checked when the ticket is written; the worker still verifies them, but no longer explores to find them. "Locations quoted are hints" becomes this.
- [x] A `## Done when` section: what the orchestrator checks before merging.

## Releases by name, map generated
- [x] A release is `releases/<release-name>.md` (stable slug, like a ticket's), with a `- **Version**: vX.Y.Z` line: renumbering edits one line, nothing moves. Its body keeps the why and a `## Handoff` section the orchestrator overwrites at each relay. It no longer lists its tickets.
- [x] Tickets stay flat in `tickets/` (a ticket changes release often; a stable path keeps links from commits and handoffs alive).
- [x] `ion repo backlog` prints the map: production version read from git (`git describe --tags origin/main`), then each release in version order with its tickets (ID, status, size, Session, Touches, title), then unplanned tickets. `--release <name>` prints one. The README keeps only the north star, the next free ID and pointers; no state a command can compute.
- [x] `ion repo update` migrates an existing backlog (annski: 105 tickets, 13 release files): release files renamed to a slug of their title, `Version` line added, each listed ticket gets its `Release` line, the release's ticket lines removed, Session moved to its own line. Idempotent, tested on a copy of annski's backlog.

## Subagent session
- [x] `ion repo session --subagent <ID>` prints the brief an orchestrator gives the `ticket` agent (user agent in `~/.claude/agents/ticket.md`): the ticket path, the effort and model from Session, notes; no merge, no question to the user, ends with the report the agent defines.
- [x] The interactive line (`ion repo session <ID>`) takes its model from Session (default `sonnet`), no longer the `MODEL` constant.
- [x] Debrief and prompt texts stop hard-coding `claude --model claude-opus-5-5`.
